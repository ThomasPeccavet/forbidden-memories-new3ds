# B135.72 TRACE-4B8 — protocole de preuve

## But

Cette version ne cherche pas encore a remplacer B135.71. Elle determine pourquoi l'etat original `DAT_8009C4B8` vaut zero alors qu'une main valide est deja dans l'OT.

Le correctif fonctionnel B135.71 reste strictement actif : si une primitive de main 52x60 est trouvee a l'entree de `FUN_80012D60` et que `C4B8==0`, le runtime ecrit encore `1` avant le finalizer.

B135.72 applique aussi une optimisation semantiquement equivalente : `C4B8` est lu avant le scan. Si le gate est deja non nul, aucun scan OT n'est necessaire puisque B135.71 n'aurait de toute facon effectue aucune ecriture. Si le gate redevient zero, le scan borne et la force B135.71 s'executent exactement comme avant. Les anciens compteurs `gate1/gate80/gate_other`, purement diagnostiques, ne sont donc plus alimentes.

Le traceur B135.72 est en lecture seule. Les tests automatiques refusent toute utilisation de `write_byte`, `write_half` ou `write_word` dans ses deux fonctions.

## Chemin original observe

```text
FUN_80012C50
  -> FUN_80012F70
       -> FUN_80015400
            -> FUN_8001522C
                 -> FUN_80015C18  (C4B8 = 1)
                 -> FUN_80015C28  (C4B8 = 0)
                 -> FUN_800150F4  (fade bit0)
  -> FUN_80012CB8
  -> FUN_80012D60                 (consomme C4B8)
```

Entree du duel :

```text
FUN_8002D0BC
  -> FUN_80032824
  -> FUN_8001591C
       -> FUN_800156F8
            -> FUN_8001569C
```

`800156F8` initialise une transition vers `0xFF` avec `EB24E=0x81`. Le vieux bridge hote `fm_service_fade_bridge()` ignore volontairement le chemin bit0. La progression doit donc venir de `8001522C -> 800150F4` original.

## Lignes affichees

```text
T72 E 22/S/C/D:a/b/c/d
T72 Q S/C/D:s/c/d G:gg Z:z
T72 RA S/C:sssss/ccccc F:xx>yy/ff
T72 RET S/C:a/b G:ss/cc ST:mm
T72 F up/u2/dn/off/w:a/b/c/d/e
T72 MAP:mmm expected:7FF
```

### Signification

- `22` : entrees de `8001522C` ;
- `S` : entrees de `80015C18`, setter original ;
- `C` : entrees de `80015C28`, clear original ;
- `D` : entrees du finalizer `80012D60` ;
- `Q S/C/D` : sequence du dernier set, clear et finalizer ;
- `G` : valeur de `C4B8` vue avant que B135.71 puisse la forcer ;
- `Z` : nombre de finalizers ayant vu zero apres un set plus recent que le dernier clear ;
- `RA S/C` : adresse de retour du dernier setter/clear ;
- `F` : `EB24C > EB24D / EB24E` lors du dernier `8001522C` ;
- `RET` : continuations post-appel observees et valeur du gate ;
- `ST` : `DAT_8009C60A` au dernier finalizer ;
- `up/u2/dn/off/w` : entrees `1569C/156F8/157D4/155F8/150F4`.
- `MAP` : presence des onze fonctions suivies dans la table native du recompileur ; `7FF` signifie qu'elles sont toutes dispatchables.

Adresses de retour attendues :

| RA | Origine |
|---|---|
| `15278` | premier set de `8001522C` lorsque la transition est active |

## Lecture du resultat

| Observation | Diagnostic |
|---|---|
| `MAP!=7FF` | au moins une fonction necessaire manque de la table native ; corriger d'abord seeds/analyse/generation |
| `MAP=7FF`, `22=0` ou `15400=0` alors que `D` augmente | fonction disponible mais appel/continuation non execute avant le finalizer |
| `22>0`, `w=0` pendant une transition `0x81` | appel indirect/direct vers `800150F4` perdu |
| `S=0` avec fade actif et gate sans bit `0x80` | branche ou appel vers `80015C18` non execute |
| `S>0`, `Z>0`, aucun clear plus recent | setter entre mais son corps/store ou sa continuation est fautif |
| sequence `C > S`, `G=0`, RA=`1531C` | clear original legitime lie a une transition vers zero |
| sequence `C > S`, RA=`15638` | `800155F8` eteint explicitement le submit |
| `S > C`, `G=1`, `FORCE` n'augmente plus | B135.71 est potentiellement supprimable |
| `S/C` augmentent mais `RET=0` | appels ARM directs; les entrees restent suffisantes pour l'ordre |
