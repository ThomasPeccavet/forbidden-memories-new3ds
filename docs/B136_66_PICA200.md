# B136.66 — optional PICA200 rasterizer

This is the first experimental hardware renderer, not a completed replacement
for PS1 GPU emulation and not a guaranteed frame-rate improvement. `PICA=0`
remains the default. Build `PROFILE=0 UNAI=1 PICA=1` for
`3ds/fm-new3ds-unai-pica.3dsx`; object directories are independent.
Requires devkitPro citro3d and the picasso/bin2s tools.

## Implemented

GP0 opaque flat/Gouraud triangles/quads and variable/fixed sprites are submitted
to PICA200 using a compiled vertex shader. Constant clip-space w preserves PS1
**affine** texture interpolation. Textures (4/8/15-bit), CLUT lookup, wrapping,
zero-texel discard and raw/modulated color are supported. A bounded eight-page
RGBA8 texture cache is immutable while the GPU may use it. A 1024x512 offscreen
hardware target stores real rasterization, not a CPU-rendered display upload.
Painter order, drawing area and offsets are preserved. No target is attached
to either LCD; existing presentation still owns TOP, and BOTTOM stays blank.

Semi-transparency, mask-set/check, texture windows, reserved texture depth,
texture-disable and flipped sprites fall back to Unai/software. Enhanced
scale/filter/wide software modes also fall back. GPU allocation failure keeps
software rendering available and is recorded in pica-status.txt.

## VRAM contract

CPU RGB555 VRAM remains the only snapshot/consumer state. On first GPU drawing
after CPU mutation it is packed/swizzled into the hardware target. Eligible
primitives are queued in order; command count and command-buffer usage bound
submission. Before software drawing, fill/copy/upload, GPU status observation,
GP1, snapshot save/load or composite presentation, queued GPU work is submitted,
waited and untiled. CPU cache is invalidated before copying the modified region
back. A software write invalidates the target and textures. Texture reads that
may depend on earlier target drawing force a feedback barrier. Cache slots
are never overwritten while submitted GPU commands can reference them.

RGBA alpha carries PS1 bit15 (1=unmasked, 255=masked); texture alpha zero means
a discarded zero texel. CPU readback restores RGB555 and bit15. Snapshot load
synchronizes *before* overwriting CPU VRAM, then discards all GPU copies. No GPU
state changes the persisted snapshot format or the BIOS/IRQ/audio scheduler.

## Known experimental limits

PICA coverage/subpixel interpolation and color modulation are not pixel-identical
to PS1/Unai. PS1 ordered dithering is not reproduced. Quads split into two
triangles; edge/diagonal seams need actual game verification. RGBA8 seed/readback
is currently a full 2 MiB transfer per synchronization; CPU conversion copies
only the affected rectangle. Frequent software fallbacks or feedback can erase
GPU gains, even regress performance. The next optimization would be tiled
ownership/partial transfer, justified by real counters; not silently dropping
readbacks or rendering twice. This version prioritizes coherent mixed rendering.

## Verification

Host tests cover all pixel-bit roundtrips, Morton tiling, packet layouts,
reserved/unsupported modes, wrapped texture and palette addressing, affine
vertices and fallback atomicity. CI compiles the PICA shader and ARM backend.
These checks do not prove GPU pixels, orientation or real performance.

Run the same combat quickstate with PICA and with `PICA=0`, inspect backgrounds,
card art/stats, menu text, transparencies, movie transitions, sound and repeated
quick-load. Read `sdmc:/3ds/fm-new3ds/pica-status.txt`: initialized=1 and growing
draws prove interception; fallback, batches, feedback_barriers and transfer byte
counts reveal synchronization pressure. Do not interpret them as FPS.
