# B135.74 — PROFILE / CLEAN

B135.74 part volontairement de **B135.71** (commit `5ccba8b`) afin de
conserver l'oracle fonctionnel du duel et son filet de sécurité sur le gate
`DAT_8009C4B8`.

## Builds

Depuis `3ds/` :

```sh
make clean
make
```

produit le build **CLEAN** : `fm-new3ds.3dsx`.

```sh
make profile
```

produit le build **PROFILE** : `fm-new3ds-profile.3dsx`.

Les deux modes utilisent des répertoires d'objets séparés
(`build-clean` / `build-profile`) pour empêcher tout mélange d'objets.

## Ce que CLEAN retire dans cette première passe

- chronométrage GP0 échantillonné B135.30 ;
- chronométrage setup/raster B135.34 et histogramme B135.35 ;
- compteurs B135.43 dans la boucle pixel des rectangles texturés ;
- profil DMA2 B135.29/32 (horloge + reset du profiler par liste) ;
- détection B135.54/55 des paquets 52x60 à chaque noeud DMA2 ;
- compteurs d'entrées générées B135.65 ;
- gros bloc console GHOT/VR6/ENV/OBJ et scans associés.

## Ce que CLEAN conserve

- B135.64 ;
- B135.66 ;
- **B135.71 intégral**, y compris le scan du hand OT et le force du gate quand
  nécessaire ;
- les correctifs GPU/GTE et le comportement fonctionnel du duel ;
- les compteurs compacts déjà utiles pour comparer la cadence globale.

Cette passe est volontairement conservative : `fm_trace_dispatch` contient
encore de la plomberie B135.56–63 dont B135.64 consomme actuellement une partie
de l'état. Elle ne sera retirée qu'après remplacement par un suivi minimal
dédié, afin de ne pas casser le duel pendant la mesure CLEAN.

## Test demandé

Utiliser exactement le même quick-state et la même séquence que B135.71.

Mesurer au minimum :

1. main immobile ;
2. déplacement du curseur ;
3. carte agrandie / attaque ;
4. tour adverse.

Pour chaque scène, noter le FPS et la durée réelle d'environ 10 secondes.
Comparer ensuite CLEAN à B135.71. Si le gain est significatif, la prochaine
passe supprimera la plomberie B135.56–63 encore nécessaire à B135.64 en la
remplaçant par un état minimal.
