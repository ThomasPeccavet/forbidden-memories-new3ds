# B135.75 — Interpreter fast path

B135.74 showed no measurable FPS gain after compiling the diagnostic probes
out of the CLEAN build. That makes the probes unlikely to be the dominant
bottleneck.

B135.75 therefore targets the fallback R3000A interpreter while preserving the
functional B135.71 duel path.

## Changes

- hot map-region chunks increase from 256 to 2048 guest instructions;
- outer chunk limit decreases from 256 to 32;
- the total per-handoff ceiling therefore stays exactly 65536 instructions;
- host time checks / result creation / main.c handoffs can occur up to 8x less
  often on long interpreter runs;
- direct PS1 RAM halfword/word accesses use fixed-size memcpy operations,
  allowing GCC to emit native ARM loads/stores instead of rebuilding values
  byte by byte;
- set_reg no longer writes gpr[0] after every ALU/load operation because the
  interpreter loop and control-flow paths already restore the zero register.

No GPU, duel-state, B135.64, B135.66 or B135.71 behavior is changed.

## Build

```sh
git switch perf/b135.75-interp-fastpath
git pull --ff-only
cd 3ds
make clean
make -j4
```

Expected label:

```text
BUILD B135.75-INTERP-CLEAN (SAFE B135.71)
```

Use the same quick-state and compare the same four scenes as B135.74:
stationary hand, cursor movement, enlarged card/attack, opponent turn.
