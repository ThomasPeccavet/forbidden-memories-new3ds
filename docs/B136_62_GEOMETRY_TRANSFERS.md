# B136.62 — specialize geometry register and scratchpad transfers

## Evidence and scope

The uploaded B136.61 capture lasted 10,026 ms, completed 390 host loops,
recorded 92 new images and dropped no rows. Its totals were 9,051 ms in
pre-guest/input execution, 2,911 ms nested DMA2, 745 ms nested sequencer,
376 ms presentation and 593 ms wait. These nested costs must not be added
again to the pre-guest total. CD sector calls were zero throughout.

The sampled native chain starting at 80057B64 ended at 80057B80 and took
about 32 ms in each of three samples. This is an inclusive chain, not an
isolated instruction or an exact total for that address. The resident MIPS
and Ghidra pseudo-C show a matrix setup via 80085558, then model primitive
callbacks via 8008A0D8 using the scratchpad at 1F800000. The capture does
not label UI phases, so it cannot establish exact map/loading/dialogue
boundaries. The 80081944 interpreted chunk includes synchronous DMA2;
its 2.915 seconds are not additional interpreter CPU overhead.

## Change

- Move the four COP2 register transfer contracts to `fm_native_gte.h` as
  shared static inline functions. The public runtime functions remain
  wrappers, so interpreter users and the external generated ABI still work.
- Rewrite direct `gte_read_data`, `gte_read_ctrl`, `gte_write_data` and
  `gte_write_ctrl` calls in generated build copies. Constant register
  operands can now eliminate the call and register switch in ARM code.
- Extend existing native memory helpers to the exact 1 KB scratchpad
  storage used by `fm_memory.c`, including physical/KSEG aliases and
  unaligned accesses wholly within the buffer. Custom callbacks, MMIO,
  BIOS and crossing spans retain the callback. Detailed cycle builds
  retain the original cycle load helpers.

No polygons, instructions, IRQs or frames are skipped. Matrix/projection
arithmetic, COP2 FIFO/sign extension/IRGB/LZCR rules and snapshots are
unchanged. The scratchpad pointer is host-only and is never serialized.
The lower screen stays blank. Build copies are regenerated by the existing
`generated-release` target; original generated sources are untouched.

## Validation and limits

A frozen B136.61 transfer implementation is compared against the inline
implementation for every 8-bit register operand over randomized backing
registers and boundary values: reads, writes and all side effects must
match. Scratchpad integration compares transformed and original generated
accesses across all three aliases and offsets, including custom callback
fallback and width boundaries, in CLEAN/PROFILE and cycle/non-cycle builds.
The ARM workflow compiles a constant COP2 fixture and rejects any remaining
external COP2 transfer reference in that fixture.

This removes overhead on a geometry-heavy path; it does not replace the
whole model callback or the rasterizer. An FPS gain is not established by
host correctness tests or by this capture. Full playback must be checked
in Azahar using the same state and route, including map, duel selection,
card animation and dialogue.
