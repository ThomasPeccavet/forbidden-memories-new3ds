# B135.82 — résultat B135.81 et trace du renderer actif

La capture B135.81 du 28 septembre montre :

```text
C2 now:800408BC first:800408BC at walker:800408BC
compiled W/R:1/0 outer:3000/457
nested W/R/C2:3000/0/457
callback:80000000 flags:C8
C2:0 head at walker:-1
```

Le pointeur de la table est correct. Le walker recompilé a trouvé la liste C2
non vide 457 fois et le renderer a été atteint 457 fois par le dispatcher
principal. `compiled R=0` explique seulement l'absence de checkpoint généré
dans `408BC` : cette fonction passe par l'interpréteur. La dernière photo a
été prise quand la liste était déjà vide ; elle ne montre pas son état pendant
les 457 appels actifs. Le callback `80000000` est suspect, sans preuve encore
qu'il était responsable de l'absence d'image.

## Test

```sh
git fetch origin
git switch diag/b135.82-c2-active
git pull --ff-only
cd 3ds
make clean
make profile -j4
```

Lancer `fm-new3ds-profile.3dsx`, commencer une nouvelle partie et parler au
premier villageois. Une seule photo des deux écrans après disparition du
dialogue suffit : la bande supérieure garde les valeurs du **dernier appel
de 408BC avec C2 actif**, même lorsque la liste devient vide.

Interprétation :

- `live/ret` : appels avec tête valide / retours observés à leur adresse RA.
  Si `pending=1`, le retour du dernier appel n'a pas encore été observé.
- `nodes/draw/bad` : objets parcourus, objets avec flags `C0`, chaîne
  cyclique ou invalide. `draw=0` indique une sélection de flags/animation.
- `last cb/fl/ra` : callback et flags du premier objet **à l'entrée de
  408BC**, ainsi que son adresse de retour. Le callback `80000000` sera
  confirmé ou écarté au bon instant.
- `last GP0/422/424` : mots GPU émis lors du dernier appel actif dont le
  retour a été observé (`pending=0`) ; passages par `422C0` et `424B8` vus dans le
  dispatcher principal. Ces deux derniers compteurs ne voient pas les
  éventuels appels ARM imbriqués et ne suffisent pas seuls à conclure.

Le chemin ne modifie pas la RAM du jeu, les pointeurs ni le rendu. Les lectures
de la liste sont bornées à 96 objets et ne sont activées qu'en build PROFILE.
