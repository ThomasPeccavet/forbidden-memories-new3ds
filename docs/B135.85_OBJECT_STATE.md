# B135.85 — état de l'objet de catégorie 2

Les captures B135.84 montrent `cat2 outer=1042`, `compiled=0`, et une liste
catégorie 2 avec un objet mais aucun drawable (`nodes/draw=1/0`) pendant le
portrait et le cadre vide. Les compteurs `gen=0` pour le renderer ne disent
rien ici : le dispatcher interprété exécute bien `80040B48`.

Cette version lit l'objet **au moment de cette entrée interprétée**. Elle
enregistre ses flags `+8`, sa catégorie `+1E`, son callback `+24`, l'adresse de
retour et le nombre de passages avec les bits `0xC0` actifs. Elle sépare aussi
les créations `800403D0(a1=2)` et suppressions `80040530` de catégorie 2,
dans les chemins recompilé et interprété. Aucune donnée guest n'est changée.

```sh
git fetch origin
git switch diag/b135.85-object-state
git pull --ff-only
cd 3ds
make clean
make profile -j4
```

Lancer `fm-new3ds-profile.3dsx`. Photographier les deux écrans devant le
portrait et le cadre vide, puis après quelques secondes sans presser de
bouton. Les valeurs `outer live/draw` sont cumulées, `obj fl/cat/cb` est le
dernier objet rencontré à l'entrée du renderer interprété, et `nodes/draw`
est l'état actuel.

- Si `outer live` augmente mais `outer draw` reste nul avec `fl` sans `0xC0`,
  l'objet est désactivé avant le dessin. Les lignes de création/suppression
  préciseront s'il a été créé puis retiré, ou si sa catégorie est incohérente.
- Si `outer draw` augmente alors que le texte manque, la catégorie 2 a été
  dessinable à un autre moment. Il faudra relier les primitives au contenu
  textuel avant d'intervenir sur les flags ou le GPU.
- `cat` différent de `2` pour l'objet en tête de la liste catégorie 2
  indiquerait une incohérence de liste ou une réutilisation d'index.

Le cadre et le portrait peuvent être produits par d'autres chemins. Un objet
catégorie 2 non dessinable ne prouve donc pas à lui seul la cause du texte
manquant. Le SDK 3DS et le disque ne sont pas présents dans cet environnement ;
les contrôles locaux sont la validation C statique et 35 tests Python.
