# B135.87 — écran noir après le dialogue

La capture B135.86 sur l'écran noir montre que le script avance (`tick=459`),
que 105 caractères ont été soumis, que l'objet texte de catégorie 6 existe,
et que son callback de glyphes `80036298` a été appelé 439 fois. Cela ne
prouve pas que les commandes GPU correspondantes atteignent le framebuffer,
mais écarte une simple absence de script ou d'objet texte.

Cette version conserve ces compteurs et relève en haut de l'écran inférieur :

- le nombre de pixels non noirs sur chacune des quatre pages canoniques
  `x=0/320`, `y=0/256`, sur la fenêtre 320×240 ;
- le nombre de pixels non noirs à l'origine exacte GP1 et dans la copie
  stable `composite` que l'hôte présente ;
- la page choisie lors du dernier latch, les nombres de latch/present/skip ;
- le compteur de frame hôte, l'attente VSync et ses complétions.

Un pixel sur 64 est échantillonné, uniquement lors du rafraîchissement de la
console PROFILE (une fois toutes les 120 frames hôtes). Les mesures sont
strictement en lecture seule.

```sh
git fetch origin
git switch diag/b135.87-black-page
git pull --ff-only
cd 3ds
make clean
make profile -j4
```

Photographier les deux écrans sur le premier cadre vide, puis quand l'écran
devient noir, puis une seconde fois quelques secondes plus tard. Ces deux
captures noires permettent de voir si `frame`, `vsync done`, `GP0` et les
compteurs texte progressent encore. Une pression unique sur ZL dans B135.86
peut également tester l'ancien chemin d'affichage, sans nouvelle compilation.

Interprétation :

- VRAM non noire sur une page, `composite=0` : choix de page ou latch de la
  copie hôte.
- `composite>0` et écran supérieur noir : présentation du framebuffer 3DS.
- Toutes les pages et la vue GP1 à zéro tandis que `GP0` augmente : commandes
  GPU, dessin hors cadre ou effacement.
- Compteur `frame` qui augmente, attente VSync bloquée sur une cible qui
  n'est pas atteinte : problème de synchronisation.
- Compteurs figés entre deux captures : blocage avant le rafraîchissement
  du diagnostic ; utiliser alors l'état de la dernière capture non noire.
