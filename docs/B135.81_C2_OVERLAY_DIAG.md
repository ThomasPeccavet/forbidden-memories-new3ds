# B135.81 — diagnostic dialogue C2 et overlay

Base : `diag/b135.80-c2-indirect` (conserve le comportement B135.71 du duel).
Cette branche ne modifie ni la table C2, ni le code guest, ni le presenter.

## Test unique

```sh
git fetch origin
git switch diag/b135.81-c2-overlay
git pull --ff-only
cd 3ds
make clean
make profile -j4
```

Lancer **`fm-new3ds-profile.3dsx`** ; vérifier le titre `B135.81` sur
l'écran du bas. Commencer une nouvelle partie, parler au premier villageois
et photographier **les deux écrans** quand le dialogue est absent. La bande
`B135.81 C2 / OVERLAY DIAG` reste en haut de l'écran du bas même si les
anciennes traces font défiler le terminal. Faire une seconde photo après le
duel si le défaut diffère. Les compteurs sont cumulés depuis le lancement.

## Lecture de la bande

| Ligne | Mesure | Décision |
| --- | --- | --- |
| `PC/RA/C2` | PC/RA actuel et nombre d'objets de la liste C2 | `C2>0` prouve que les objets existent ; `C2=0` oriente vers création/état de scène. |
| `head at walker` | tête C2 au dernier appel recompilé de `41674` | Une valeur négative signifie que le walker n'avait aucun objet à cet instant. |
| `C2 now/first/at walker` | pointeur renderer à `800923E0`, au premier puis au dernier appel | Attendu : `800408BC`. Une valeur différente **au moment du walker** oriente vers initialisation/table/chargement. |
| `compiled W/R` | présence des deux entrées dans le dispatcher statique | `R=0` avec pointeur `800408BC` oriente vers génération/dispatch ou fallback. |
| `outer W/R` | passages dans le dispatcher principal | Peut rester à zéro pour les appels ARM imbriqués : ne suffit pas à conclure. |
| `nested W/R/C2` | appels de `41674`, `408BC`, appels walker avec liste C2 non vide, mesurés dans les checkpoints générés | `W>0`, `C2>0`, `R=0` avec pointeur correct oriente vers l'appel indirect ou son checkpoint ; `R>0` oriente vers objet/OT/GPU. |
| `Wra/Rra`, `callback/flags` | adresse de retour des appels, callback et flags du premier objet valide observé par le walker | Isoler un callback nul, une table modifiée ou un chemin d'appel inattendu. |
| `OV atW/now` | premier mot RAM à `80180000` lors du walker et actuellement | Une variation signale un changement d'image possible ; une valeur seule ne prouve pas l'identité ni l'intégrité de l'overlay. |
| `GP0 rect/quad` | compteurs cumulés du GPU | Ils incluent d'autres scènes ; comparer les deux captures, ne pas les interpréter seuls. |

Si `nested W=0` alors que `outer W>0`, le checkpoint généré n'a pas été
atteint ; un `nested R=0` n'est alors **pas** une preuve que `408BC` ne tourne
jamais. Si `C2 now` et `C2 at walker` diffèrent, rechercher qui écrit la table
pendant la transition plutôt que de corriger le rendu graphique.

Les lectures du premier objet sont limitées aux index `0..95` et la trace
du checkpoint n'est active que pour `make profile`. Le build standard reste
sans cette instrumentation de chemin chaud.
